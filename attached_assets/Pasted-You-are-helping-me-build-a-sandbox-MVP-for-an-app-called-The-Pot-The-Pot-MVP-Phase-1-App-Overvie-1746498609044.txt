The Pot – MVP Phase 1 App Overview (For Replit AI + Devs)

App Name: The Pot

Version: MVP Phase 1 – Sandbox Testing
Purpose:
The Pot is a digital group savings app built to help users pool money toward shared goals, with structured payout systems, flexible governance, and transparency at every step. The MVP focuses on enabling users to create “Pots,” select how payouts are handled, and simulate deposits and withdrawals in a risk-free sandbox mode using dummy coins.

Core Features of the MVP:
1. User Registration & Login
• Name, email/phone, and password
• Onboarding to create or join a Pot

2. Create or Join a Pot
• Pot Name, Description, and Target Goal
• Invite others by phone or email
• Select Payout Structure (see below)
• Select Withdrawal Approval Method (democratic vote, admin, or timed)

3. Payout Structures – The 3 Methods of Withdrawal
These define how the pooled funds will be distributed once the withdrawal is triggered:
A. One-to-Many:
• One user deposits (e.g., a club leader or parent)
• Funds are evenly or selectively distributed to all members in the Pot
• Use case: disbursing allowances, event stipends, club budgets

B. Many-to-One:
• Multiple users deposit into the Pot
• One recipient gets all the funds (e.g., someone receiving a gift or financial support)
• Use case: birthday surprise, emergency fundraiser, peer-to-peer backing

C. Many-to-Selected:
• Multiple users deposit into the Pot
• Funds are distributed only to select users (e.g., group trip costs for certain members)
• Use case: shared expenses where not everyone receives money back

Each Pot setup must define one of these payout methods before deposits begin.

4. Withdrawal Approval System:
These determine how funds are released from the Pot:
• Democratic Vote: All members must vote; a set majority threshold must be reached for withdrawal to occur.
• Admin Approval: The Pot creator or designated admin has sole authority to approve or deny withdrawals.
• Timed Release: Funds cannot be withdrawn until a preset time/date is reached.

5. Sandbox Transactions:
• Dummy coin deposits/withdrawals
• Simulated errors (e.g., failed deposit, vote not passed, invalid timing)
• Developer logs + user-facing messages

6. Activity Logs & Confirmation Flows:
• Logs show deposits, votes, approvals, errors
• Confirmation screens guide testers through the experience
